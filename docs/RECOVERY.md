# Failure recovery

What to do when a phase fails mid-run. The rollback stack handles most
cases automatically, but if it can't — or if you killed the process
mid-flight — this document lists the manual undo commands for each
destructive step the tool can take.

## First, read the log

The log file is printed at startup and again on exit; default location
is `/var/log/btrfs-migrate.log`. It records every external command in
time order, prefixed with `RUN:` (executed) or `DRY-RUN:` (announced
only). The last `RUN:` line before the failure tells you exactly how
far the destructive sequence got.

The rollback stack, when it runs, emits `ROLLBACK:` lines in LIFO order.
If you see rollback entries at the end of the log, the tool has already
undone its work — treat the disk as it was before the run started.

## Partial LUKS format

You hit the failure after `cryptsetup luksFormat` but before anything
else. If the rollback stack ran, `cryptsetup close cryptroot` was
already called and the mapping is gone. The LUKS header, however, is
persistent on the partition. Manual undo:

```sh
cryptsetup close cryptroot              # if still open
wipefs -a /dev/sdaN                     # erase LUKS2 signature
```

If you want to keep the header (plan to retry with `--luks-reuse`),
skip the `wipefs`.

## Partial mkfs.btrfs

A failed `mkfs.btrfs` leaves the partition in an indeterminate state.
The tool refuses to re-run `mkfs.btrfs` on an existing btrfs without
`BTRFS_MKFS_FORCE=1` — that guard exists specifically for retry-after-
failure scenarios.

Recovery options:

1. **Retry with override:** `BTRFS_MKFS_FORCE=1 ./btrfs-migrate.sh
   ...`. The tool will `wipefs -a` and re-mkfs.
2. **Bail out entirely:** `wipefs -a /dev/sdaN` (or the mapped device
   for LUKS runs), re-partition if needed.

## Partial rsync into @ subvolume

rsync was interrupted. The target tree is incomplete. The tool's
post-rsync integrity check (introduced in v0.2.0) will catch this on a
re-run. To clean up manually:

```sh
mount -o subvolid=5 /dev/sdaN /mnt/target
btrfs subvolume delete /mnt/target/@          # removes the partial @
btrfs subvolume delete /mnt/target/@home      # and its siblings if any
umount /mnt/target
```

Then re-run the tool; it will re-create subvolumes and re-rsync from
scratch.

## Partial fstab managed block

The tool writes its entries into a marked block between:

```
# BEGIN btrfs-migrate managed fstab entries
...
# END btrfs-migrate managed fstab entries
```

If a run was killed between writing the block and unmounting, the
block is present but may be truncated. Manual undo:

```sh
mount -o subvolid=5 /dev/sdaN /mnt/target
# open /mnt/target/@/etc/fstab in your editor and delete the block
# between the BEGIN and END markers
```

A re-run will regenerate the block idempotently (replace-in-place, not
append).

## Bootloader installed but broken

The most common "help, I can't boot" scenario: bootloader wrote a
config referencing the new Btrfs root but the initramfs doesn't have
LUKS hooks, or systemd-boot wrote an entry pointing at a kernel path
that doesn't exist.

### Boot back into the old system

If the old EXT4 root still exists on a different partition:

1. Reboot into the BIOS/UEFI boot menu.
2. Select the firmware entry for the old disk (or the old entry in
   GRUB's menu — `grub-mkconfig` usually preserves `os-prober`-found
   alternatives).
3. Once booted, inspect `/var/log/btrfs-migrate.log` on the old system
   and the ESP's loader entries (`/boot/efi/loader/entries/` for
   systemd-boot, `/boot/grub/grub.cfg` for GRUB).

### Chroot into the new system to fix things

If you can't boot either system, use the install ISO:

```sh
# Boot the Live ISO, become root.
cryptsetup open /dev/sdaN cryptroot         # if LUKS
mount -o subvol=@ /dev/mapper/cryptroot /mnt
mount /dev/sdaBOOT /mnt/boot
mount /dev/sdaEFI  /mnt/boot/efi            # UEFI
for d in proc sys dev dev/pts run; do mount --bind /$d /mnt/$d; done
chroot /mnt /bin/bash

# From inside the chroot:
update-initramfs -u -k all                  # Debian/Ubuntu
mkinitcpio -P                               # Arch

update-grub                                 # Debian/Ubuntu
grub-mkconfig -o /boot/grub/grub.cfg        # Arch
bootctl --esp-path=/boot/efi update         # systemd-boot

exit
# Clean up:
for d in run dev/pts dev sys proc; do umount /mnt/$d; done
umount /mnt/boot/efi /mnt/boot /mnt
cryptsetup close cryptroot
```

## Snapper or grub-btrfs install half-finished

`phase_snapshots` runs late in the sequence and is intentionally
permissive — its failures are warned-not-died because the migrated
system is already usable without them. If Snapper packages installed
but the config wasn't written, re-run `snapper create-config /`
manually; the tool's config is idempotent and can be regenerated by a
second pass.

## When in doubt

Re-running the tool is usually safe:

- `mkfs.btrfs` refuses to overwrite without `BTRFS_MKFS_FORCE=1`.
- `cryptsetup luksFormat` would fail on an existing header unless you
  manually wipefs or use `--luks-reuse`.
- `fstab` writes are idempotent replace-in-place.
- rsync is append-and-update; re-running will re-walk the tree and
  bring partial copies to completeness.

Before every retry, read the log's last `RUN:` lines so you know what
state the disk is actually in.
